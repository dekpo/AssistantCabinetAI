## Rule for whoever writes a test

**Exact commands in a human test (owner instruction, 11 October 2026, binding for every agent, in every lot).** The owner ran lot 5's test and lost time looking for commands that were abbreviated. Every step of a human test, in the protocol file **and** in the chat message, is complete and copy-pasteable:

1. **Every command is written in full**, from the repository root, with the exact path of the script and the exact name of the sub-command, for example `python docs\test-reports\knowledge-base-pass-1\human-tests\lot05_helper.py stop-ai`. Never `stop-ai` alone, never `lot05_helper.py ...`, never "the script".
2. **Every "in the script" or "look at the output" names the script and its arguments**, for example `python docs\test-reports\knowledge-base-pass-1\human-tests\show_kb_entities.py` or `show_kb_tables.py`. Say which of the two to run; if both are needed, say both.
3. **Every click is named by the exact label of the interface** (button, card, menu, tick box), and the card or screen it is on.
4. **Every expected result has been checked against what the application really does**, not against what the code should do: for example, with the AI machine stopped the application shows its own red connection banner (« Aucune réponse de l'IA ... ») whatever the analysis does; a test that says "no banner" there is wrong. If you cannot observe it, say so in the step instead of promising it.
5. **The chat message and the protocol file give the same steps in the same order with the same commands.** The chat message is the one the owner follows; it is never a summary of the file.
6. A command that must be typed has been run by the agent (on temporary folders) and its output is known; a name that is easy to mistype (`stop-ai`) is written out and copy-pasteable on its own line.
7. A step that stops or restarts a service gives the full command to put it back.
8. **Never ask the owner to run what the agent already ran (owner instruction, 11 October 2026, binding for every agent, in every lot and every fix).** `cargo test`, `cargo clippy`, `pnpm run test`, `pnpm run build`, `pytest` and any other automated suite are run by the agent, whose numbers go in the lot report ("Verification"); they are **not** a "Part A" of a human test, because their output is long and adds nothing she can check. A human test contains only what the agent cannot see or do: clicks and screens of the real application, the output of the read-only inspection scripts, answers to questions typed in the interface. The one exception is an automated command the owner must run **herself for an explicit reason** (for example a benchmark on her own machine, or a build that only her hardware can make); the step then states that reason in its first sentence.
9. **A human test is a script, not a list (owner instruction, 11 October 2026, binding for every agent, for every human test of the repository, KB lots and every other work).** The owner follows the steps to the letter, one after the other, and cannot guess what comes next: a test whose order or state is wrong wastes her time and proves nothing. Therefore:
   1. **Linear and stateful.** The protocol runs top to bottom. Every part opens with **"You start with"** (the exact state: application open or closed, mode, folders pointed at, what is ticked) and closes with **"You leave with"**. A part's "You start with" is the previous part's "You leave with"; the agent checks this chain before proposing the test.
   2. **No undo in the middle.** Backup at the start, **one** restore at the very end. An optional part goes **last** and brings its own undo of exactly what it changed; no later part may depend on a state an optional part changed or undid. A step that changes a setting, a folder or a selection says the resulting state, and a selection (what is ticked) is restated in every step that depends on it.
   3. **Expectations come from her real state, not from an assumed empty one.** Either the protocol sets a known state first (a Reset, a backup and a `prepare` command), or the expectation is a rule ("0, or 1 if your Data folder was analysed before") and not a bare number. When she sent earlier screenshots or outputs, they are read before the numbers are written.
   4. **Every question has been run through the real path.** Which route a question takes (the folder router can read a person's name as a file name) is checked with the code, not assumed; a question that takes another route than the one the step is about is replaced.
   5. **The agent walks the whole protocol before proposing it**: every helper command in order on temporary copies of the settings and the index (with the `ACAI_*` overrides), every part's start state compared with the previous part's end state, every expected figure produced by the same code on the same files. A step the agent could not walk says so in the step.
   6. **A deviation she reports is a finding about the protocol first.** The agent says which of the two (the product or the protocol) was wrong, fixes the protocol, and gives the short ordered re-run it now needs, with the state to start from.
