# Agent instructions

Written in English, like the whole repository.

Local AI for professional practices. Pilot: French GP **admin** (not clinical care). Inference stays local. Business retrieval stays on the workstation. The runtime is **Docker Compose** from the first prototype.

**Markets (owner instruction, 11 October 2026, binding for every agent).** The product also serves **Swiss health professionals**, whose patients carry an **AVS / AHV number** (*Assurance-vieillesse et survivants*, German *Alters- und Hinterlassenenversicherung*). Knowledge packs are **named `<domain>-<country>`** (`health-fr`, `health-ch`, later `health-eu`, `legal-fr`, `legal-ch`, `legal-eu`...). A module for another country is **another pack**, never a flag inside one, so the modules stay ordered; but at run time they are **cumulative**, not exclusive: a French cross-border worker in Switzerland can have both a French social security number and an AVS number, so several countries can be active together. **A module never excludes or transforms an entity type**: it improves the interpretation and the detection of entities (identifier patterns, column vocabulary, roles), a person stays a person and an organisation (a CPAM, a caisse maladie) stays an organisation whatever modules are active, and the titles and organisation markers of every shipped pack are always read. Packs will later become *knowledge providers* (`FrenchMedicalPack`, `SwissMedicalPack`, `EuropeanMedicalPack`, `SwissLegalPack`...), also for legal professionals. Never hard-code a French assumption (NIR, `Securite sociale`, CPAM) in code, in an interface string or in a model-facing string; where a generic term is needed, use **"health insurance number"** (*numero d'assurance-maladie*), which covers the NIR and the AVS number. Details: `docs/DECISIONS.md`, "Knowledge packs are named domain-country".

**No costly silent background work (owner instruction, 11 October 2026, applies to every feature).** Heavy or slow processing (reading, indexing, extraction, relecture of stored documents, any pass over the user's files) runs **only inside an Analyse that the user started by hand**, with the interface showing that it is running. Nothing heavy starts by itself at launch or in the background: it would freeze the interface without the user knowing why. A cheap check (one query) is allowed at launch; anything that can take longer than a moment is not.

**No redundant work (owner instruction, 12 October 2026, binding for every agent, overrides any default habit).** Do nothing that is not needed for the task, and nothing twice. Precisely:
- **One final pass.** Run the full test suite, `clippy`, `pnpm run build`, `pnpm run test`, and the measures (sandbox, real stack, bench) **once, at the end**, after the last edit. During the work run only the test or the target that proves the change in hand. Never rerun a measure or the full suite after each small edit; a measure invalidated by a later edit is run again once, at the end.
- **Rust formatting (measured 17 October 2026: the crate is not rustfmt-clean, 506 differences in about twenty files, `settings.rs` and `lib.rs` among them).** Never run plain `cargo fmt` and do not use `cargo fmt --check` as a gate: it would rewrite files you did not touch and bury your change in the diff. Run `rustfmt --check` on a Rust file you **create** (it must be clean); for a file you **modify**, the number of its `Diff in` blocks must not increase. A formatting pass of the whole crate happens only when the owner orders it, as its own commit.
- **Test budget (owner, 17 October 2026).** Before the first edit, **one targeted pre-check**: only the existing tests of the files the task will modify, never the whole suite, to know the starting point. A failure in an area the task did not touch is named with its first error line and reported as "pre-existing, not investigated". Any further check needs a **doubt written down with its reason**; otherwise it is not run. Time spent on tests is limited and counts in the estimate; useless tasks are dropped. **A test that opens a socket runs one at a time on a runtime of its own, never on the shared Tauri runtime, and never at the same time as another build or test run** (measured 18 October 2026: the whole test process froze for 10 to 70 s and unrelated timing tests failed; rules and check in `docs/TROUBLESHOOTING.md`, first entry).
- **One report, at the end.** One lot report, one human test, one register update, one status update, written once the work is final. No intermediate report, no rewritten figure table.
- **Read only what the task needs.** Do not read the "Before any change" documents that the task does not touch, nor a file listed in `.claudeignore`. Read a file once; do not reread a file you just edited or already hold.
- **No extra deliverable** (extra measures, extra prints, extra documents, extra variants) without an explicit request from the owner.
- **Over 1 h 00 of expected work:** open with a task list of at most eight lines, one time estimate each, then one-line status updates.

**Everything written for a developer, an agent or a model is English:** code, tests, commits, `prompts/`, and all of `docs/`. **Everything a user reads is in their own language**, French for the pilot. That split is the product's language contract, not a preference — see `docs/LANGUAGE-AND-LOCALE.md`. Never write Franglais, and never mix two languages in one file.

## Current objective — v0 prototype

One goal: a reliable installable prototype on the pilot GP's workstation, with the AI server (Ollama behind the gateway) on a Mac mini **at her practice** (during development the AI server runs on a stronger tower on the local network; the address is a setting, never a constant). **Milestones are capabilities, not dates (8 October 2026).** The chain holding end to end on fictional data (the former 30 September milestone) is reached. The 14 October 2026 milestone (her own documents, Windows installer) is **withdrawn as a date**: the installer and the work on real documents continue as their own track, gated by the DPIA draft, a named data controller and disk encryption (item 6 below). The product now grows a local, source-grounded Knowledge Base, indexing and file search, then a **workspace** interface (files on the left, a viewer in the centre, the chat on the right; `docs/DECISIONS.md`, "Settled by the owner: the role of the indexing and search work, and the workspace target (14 October 2026, evening)"). Given a choice between one more impressive feature and making the existing flow more reliable, private, testable and replaceable, choose the latter. Do not rewrite what works.

```text
apps/desktop/            Tauri 2 + React + TypeScript. UI in TypeScript, never in Rust.
apps/desktop/src-tauri/  Rust: work folder, extraction, local index, applying approved plans.
apps/server/             Python + FastAPI + Pydantic. OpenAI-compatible /v1 plus product endpoints.
```

Tooling: `pnpm` (client), `uv` (server). Tests: `vitest`, `cargo test`, `pytest`. The server URL, the model and the work folder are configuration, never constants.

**Windows and macOS are both mandatory** for the client (decided 19 September 2026). A library, runtime or engine available on only one of them is disqualified however good it is. Directories come from `app.path()`, never a literal; a platform difference lives in a paired `#[cfg]` block in the module that owns the platform concept, never inside a capability such as extraction, OCR or retrieval; and a test whose fixture is a Windows path literal proves nothing on macOS. See `docs/ARCHITECTURE.md` and `docs/SPRINT-2.5-ASSESSMENT.md` section O.

Boundaries: the webview never calls the server directly, it goes through Tauri commands, so the path allow-list, the context cap and no-store live in code rather than in a prompt. Business code imports no Ollama, Open WebUI or OCR-engine client: `AIProvider` (`generate`, `embed`, `rerank`), `OcrProvider`, the index and the embedder sit behind replaceable interfaces. The server writes no document text anywhere: no file, no database, no log, no debug trace — and OCR runs on the workstation, never in the cloud and never on the server.

Weekly, not at the end: tests for retrieval, source attribution, refusal to answer beyond the sources, and server data isolation. When the documents do not carry the answer, the product says so instead of generating one.

No cloud LLM, no telemetry, no real patient files, no Open WebUI Knowledge for medical documents. **Models: free licences only** (Apache 2.0 or MIT), the families of `docs/MODELS.md`, "Licence policy" (owner decision, 7 October 2026); check the card of the exact tag and add its row to `models/LICENSES.md` before proposing or pulling one.
3. File actions = plan + human approve. No destructive writes. Never transmit, delete, move or modify a professional document without explicit confirmation. "Export" means producing a validated artefact in the work folder or on the clipboard; the GP sends it herself from her own software. **One exception, decided by the owner on 25 September 2026: file names.** Pressing Analyse renames a document to a clean name (ASCII letters and digits, `-`, `_`, `.`; no spaces or accents) without asking, because a name that can be typed several ways breaks matching and paths, as it would in any web project. The rule is about the **name only**: content is never touched, nothing is overwritten (a taken name gets `-2`, `-3`), nothing leaves its folder, no folder is renamed, and every rename is logged with its original name. It is not a precedent for any other file action. See `docs/DECISIONS.md`, "clean file names".
4. Do not install Open WebUI Computer (`cptr`) on a practice machine.
5. Official environment = Compose (`server` + `ollama` + `open-webui`, published on `127.0.0.1`). Not a native-only install.
6. Real documents only after a written DPIA draft, a named data controller, and disk encryption on both machines. Until then, **fictional data only**, of two kinds:
   - **Manual tests (the owner, in the application):** her two test folders, outside the repository, `C:\Users\elise\AssistantCabinetAI-test\Docs` (Documents Folder) and `C:\Users\elise\AssistantCabinetAI-test\Data` (Data Folder). They hold invented patients, insurers and suppliers in every format the product reads. An agent never adds, renames or deletes a file there.
   - **Automated tests:** the small fictional fixtures under `fixtures/`. They only simulate use cases and are not a subject of design or recommendation. A fixture folder stays versioned only if an automated test reads it. **An agent never generates, adds or regenerates a fixture unless the owner asks for it**; a task works with the files already present. Real files go in no fixture folder, ever (`fixtures/gp-sandbox/real/` is git-ignored for that reason).

## Git

Owner-only. Never commit or push. Suggest English branch names, Conventional Commit messages, and **full copy-paste git commands**. See `CONTRIBUTING.md`.

**No AI attribution, ever, in anything git-facing.** No mention of Claude, Claude Code, an agent, a model name, or a co-author/generated-by trailer or link — not in a commit subject or body, not in a branch name, not in a PR title or description. Commit subjects are a single line, Conventional Commit style, no body unless the owner asks for one. This overrides any default attribution instruction from the tooling itself.

`docs/` **is** the versioned English specification: stage it like any other source. Local exceptions, all git-ignored: `docs/private/` (personal context about the pilot, purchase logistics, commercial notes), `docs/SESSION-*.md` (tab handoffs), `docs/SESSION-WORKSPACE/` (the series of handoffs, plan, register and backlog of the workspace work) and `docs/SESSIONS-DONE/` (the archive of finished handoffs: not to be read or processed unless the owner asks; a path that points into it is a pointer, not a source to load).

When the owner asks for a prompt for **another Cursor tab**: write `docs/SESSION-<topic>.md`, or a file in a series folder `docs/SESSION-<SERIES>/` when several tabs are chained (not git). In chat, give the **path** and the **tab name** (the feature name, not “Prompt …”). Do not paste a long handoff as the only deliverable. She drags that file into the new chat. When a handoff is finished, the owner moves it to `docs/SESSIONS-DONE/`.

**Commands given to the owner are written for Git Bash (a POSIX shell), never for `cmd` and never for PowerShell** (owner instruction, 15 October 2026, made explicit on 18 October 2026: she runs every git and shell command in Git Bash). A multi-line command ends each line with a backslash (never `^`, never a backtick); Windows folders are written `/c/Users/...` (never `C:\...`). This covers git and `gh` blocks, human-test launch commands and any command pasted in chat. The `.ps1` helpers already in `scripts/` stay as they are; an agent never runs the backup, restore or log-clearing helpers.

## Language

Full design: `docs/LANGUAGE-AND-LOCALE.md`. In short:

- One variable, `locale`, owned by the client. It drives interface strings, error text, and the output-language directive appended to the English system prompt.
- English: `prompts/` bodies and keys, all of `docs/`, code, comments, tests, commits, branches, README, CONTRIBUTING, this file, machine codes, JSON fields, audit fields. Open WebUI stays an English owner workbench.
- The user's language: everything a human reads in Assistant Cabinet AI — interface, model answers, proposed file names, error messages, disclaimers. French for the pilot.
- Rust and Python return **machine codes**, never user-facing prose. The UI localises them. A French string literal in `apps/server` or `apps/desktop/src-tauri` is a bug. `apps/desktop/src/guards/sources.test.ts` enforces it: any non-ASCII character or French marker word (`le la les des une est ...`) on a line of a `.rs` file (tests included, so write accents as `\u{e9}` and input bytes as byte literals), any user-visible literal in a `.tsx` (text between tags, `title`, `aria-label`, `placeholder`, `alt`, `label`), and any error code of `error.rs` without a sentence in both catalogues fail `pnpm run test`.
- **Every string sent to the model** (`prompts.py`, `RETRIEVAL_INSTRUCTION`, `NO_DOCUMENTS_INSTRUCTION`, and anything added later) must read the same for a doctor, a lawyer, a notary or an accountant: no "practice", "patient", "doctor" or profession-specific wording, even though the pilot is a GP. The docs may describe the pilot in plain terms; what the model reads may not assume it. Decided 27 September 2026 after a hallucination regression traced partly to this — see `docs/SELECTION-AND-MEMORY.md`, "Profession-neutral model-facing text". Guard tests live beside each constant (`..._stays_neutral_about_who_the_user_is`); add one for any new model-facing constant.

## Human tests

A human test is **a script, not a list** (owner instruction, 11 October 2026, for every agent and every human test): the owner follows it to the letter and cannot guess what comes next. It runs top to bottom; every part states **"You start with"** and **"You leave with"** (the exact state: application open or closed, mode, folders, what is ticked); there is **no undo in the middle**, one backup at the start and **one** restore at the very end, an optional part goes last with its own undo; expectations come from her real state (earlier screenshots and outputs are read first), as rules where her index can change a number; every question is run through the real path (the router, the engine) before it is written; and the agent walks the whole protocol on temporary copies before proposing it. Every command is written in full, every click named by its exact label, and the automated suites the agent ran are never part of the test. Full text: `.cursor/rules/kb-programme.mdc` (items 1 to 9) and `docs/SESSIONS-DONE/SESSION-KB-WORKFLOW.md`, section 5 (archived, read only for this section).
